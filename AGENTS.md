# AGENTS.md

Краткие постоянные инструкции для ИИ-агентов в этом репозитории.

## С чего начинать

Перед исследованием задачи:
1. Прочитай этот файл и только релевантный раздел в `docs/`.
2. Используй `docs/codebase-map.md` для выбора подсистемы.
3. Изучай только файлы, связанные с задачей.
4. Расширяй область чтения только при явной необходимости.

Не перечитывай всю архитектурную документацию для каждой локальной правки.

## Навигация

- Общая архитектура и потоки: `docs/architecture.md`
- Быстрый индекс по задачам и файлам: `docs/codebase-map.md`
- Продуктовый контекст и запуск: `README.md`

Если карта указывает конкретный модуль, начинай с него, а не с корня проекта.

## Экономия контекста

- Не читай весь репозиторий повторно.
- Не открывай большие файлы целиком без необходимости.
- Предпочитай точечный поиск и чтение диапазонов.
- Не повторяй уже выполненное исследование в рамках сессии.
- Не загружай большие логи и артефакты без причины.
- Не анализируй нерелевантные тесты.
- Не читай файлы `*.test` без прямого запроса пользователя.
- Не выводи большие фрагменты исходников без необходимости.
- Не запускай дорогостоящие команды без причины.

## Точность

Документация здесь — навигационный индекс, а не абсолютный источник истины.

- При изменениях всегда сверяйся с актуальным кодом.
- Если Markdown и код расходятся, приоритет у кода.
- Не принимай архитектурные решения только по устаревшим заметкам.

## Изменения кода

Перед изменением:
1. Определи затрагиваемую подсистему.
2. Проверь её интерфейсы и зависимости.
3. Найди ограничения и побочные связи.
4. Меняй минимально необходимую область.
5. Проверь последствия для соседних компонентов.

Не делай несвязанный рефакторинг.
Не меняй публичные контракты без необходимости.

## Обновление документации

После значимых архитектурных изменений:
- обновляй релевантные разделы в `docs/architecture.md` и/или `docs/codebase-map.md`;
- исправляй устаревшие ссылки и пути;
- удаляй неактуальные утверждения.

Не создавай новые Markdown-файлы без явной пользы для навигации.
Не обновляй документацию при чисто косметических изменениях.
